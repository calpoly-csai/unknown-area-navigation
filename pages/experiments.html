Gemini vs. OpenAI Comparative Experiment

Setup

This experiment evaluates two cloud-based vision-language models on their ability to assess road traversability from a single image. The two models evaluated were gemini-2.5-flash-lite (Google Gemini API) and gpt-4.1-nano (OpenAI API).

The test set consisted of 9 images drawn from a set labelled test1–test10, with test4 excluded as it was unavailable at the time of the experiment. Each model was called sequentially via its respective API using the same shared prompt:

"Analyse this image for an autonomous vehicle. Reply with a JSON object with exactly these fields: description, traversable (true/false), justification. Return only the raw JSON, no markdown fences."

Timing was measured as wall-clock time per API call using time.perf_counter(), capturing the full round-trip latency from request dispatch to response receipt.

Error Analysis

Gemini errors:

  • test1 — A person in a morph suit standing next to a novelty pedestrian sign. Gemini judged the scene traversable, reasoning that the signage and person did not obstruct the road. The model failed to recognise the pedestrian-adjacent hazard as a reason to stop. This reflects an over-permissive tendency in ambiguous pedestrian scenes.
  • test7 — A graffiti-covered bridge. Gemini judged it non-traversable, citing structural concerns based on the graffiti. The bridge was in fact passable; the model over-indexed on visual degradation as a proxy for structural unsafety, demonstrating over-caution when surface appearance is unusual.

OpenAI errors:

  • test9 — A woman hitchhiking on the roadside with a clear road ahead. OpenAI judged the scene non-traversable, citing the woman's proximity to the road as a hazard. The road itself was clear and the correct judgment was traversable. This reflects over-caution in scenes with roadside human presence.

Both models performed well on clear-cut cases (fallen tree, flooded road, livestock, aircraft on road) and struggled only on edge cases involving human presence or ambiguous infrastructure. Given near-identical latency profiles, accuracy is the primary differentiator, favouring gpt-4.1-nano for deployment in traversability assessment pipelines.

Demo Pipeline 1

Demo Pipeline 1 (mainDemo1.py) is the first end-to-end unknown-object navigation pipeline. It combines a single-model object detector with a cloud vision-language model to make real-time traversability decisions from a live webcam stream. The pipeline has four key architectural components:

Three-State YOLO Confidence Classification

Object detections from YOLOv8s-worldv2 are classified into one of three states based on confidence score:

  • Known (confidence ≥ 50%): The object is identified with sufficient confidence. No further action is taken; the detection is displayed with a blue bounding box.
  • Candidate unknown (25% ≤ confidence < 50%): The object is detected but cannot be confidently classified. It is flagged as a candidate unknown and displayed with an orange bounding box. A per-object streak counter begins incrementing.
  • Ignored (confidence < 25%): The detection is treated as noise and silently dropped.

This three-state classification uses YOLO confidence as a proxy for out-of-distribution detection: an open-vocabulary detector that assigns low confidence to a region is effectively signalling that the object does not closely match any known category.

Gemini Traversability Assessment

When a candidate unknown object is confirmed (see streak logic below), a snapshot of the current frame is sent to Gemini 2.5 Flash Lite via the Google Generative AI API. The model is asked to return a structured JSON response containing a scene description, a binary traversable judgment, and a one-sentence justification. The traversability verdict is displayed as a persistent banner on the live stream until a new query completes.

Streak-Based Confirmation

A candidate unknown object must appear in 8 consecutive frames before it is treated as a confirmed unknown and triggers a Gemini query. The streak counter resets to zero as soon as no candidate unknown is detected in a frame. This requirement filters out transient detections — a person briefly walking through the frame will not trigger the VLM assessment; only objects that persist in the scene will.

API Cooldown

A 5-second cooldown is enforced between consecutive Gemini API calls. Once a query is dispatched, no further queries are sent until the cooldown has elapsed, regardless of whether new confirmed unknowns are detected. This prevents excessive API usage during scenes where an unknown object remains persistently in frame. The remaining cooldown time is displayed in the bottom-right corner of the stream overlay.
