Unknown Object Detection

Problem Statement

Standard closed-vocabulary detectors are trained on fixed class sets. When presented with an out-of-distribution object — one that does not appear in the training data — these models do not abstain or express uncertainty; instead, they assign the nearest known class label to the object with whatever confidence the model can muster. This silent mislabelling is the core problem the subsystem addresses: a robot acting on a wrong label may treat an unknown obstacle as a familiar, benign object and navigate into it. The goal of this subsystem is to detect when the model is uncertain and flag the object as unknown rather than producing a confidently wrong classification.

Approaches

Approach 1 — Confidence-Thresholded YOLO-World

This approach uses YOLO-World's open-vocabulary confidence scores as a proxy for model certainty, treating low-confidence predictions as evidence of an out-of-distribution object. The detection mechanism flags any bounding box whose confidence score falls below 50% as an unknown object, displaying it in red, while detections at or above 50% are labeled with the predicted class name. The intended use case is real-time webcam inference on standard CPU/GPU hardware where a single model is sufficient and a simple, interpretable threshold is preferred over a more complex multi-model pipeline.

Approach 2 — Dual-Model Consensus (NanoOWL + YOLO-World)

This approach combines a class-agnostic detector (NanoOWL) with a class-specific detector (YOLO-World) so that objects found by the agnostic model but unmatched by the class-specific model can be flagged as unknown. The consensus mechanism works as follows: NanoOWL detects any generic object presence; each NanoOWL bounding box is then matched against YOLO-World detections using IoU overlap — objects detected by NanoOWL but unmatched by YOLO-World (IoU below IOU_MATCH_THRESHOLD of 0.20, or no YOLO detection at all) are flagged as unknown. The intended use case is scenarios where higher recall on unknown objects is required and the additional compute cost of running two models in parallel is acceptable.

Approach 3 — Baseline Closed-Vocabulary YOLO

This approach runs a standard YOLOv11n model on a live webcam feed with no unknown-object logic whatsoever, serving as a reference point for the limitations the other approaches aim to overcome. The mechanism is straightforward: the model assigns the nearest known class label to every detected object with no mechanism to express uncertainty or flag out-of-distribution inputs. The intended use case is as a baseline that illustrates the core limitation — silent mislabelling — motivating the development of Approaches 1 and 2.

Approach 4 — Frame-to-Frame Colour Histogram Comparison

This approach detects scene changes by comparing the colour distribution of consecutive webcam frames, flagging any significant shift as a potential unknown-object event without requiring a pretrained model. The flagging mechanism computes the Bhattacharyya distance between the 3D BGR colour histograms of consecutive frames (8 bins per channel, L1-normalised); when the distance exceeds a threshold of 0.1, the text "Color Changed" is overlaid on the stream for 0.5 seconds. The intended use case is as a lightweight, model-free change-detection pre-filter that can run on any hardware without a GPU, signalling that a more expensive detection pipeline should be invoked.

Limitations

  • Evaluation was entirely qualitative — approaches were assessed by presenting niche or unusual objects to a live webcam and observing detection behaviour. No standardised benchmark dataset was used, so no quantitative performance metrics (precision, recall, F1) are available for any of the four approaches.
  • NanoOWL was run on CPU rather than its intended deployment target of NVIDIA Jetson edge hardware. Inference on CPU is significantly slower, which constrained the frame rate and limited the practical usability of Approach 2 in real-time scenarios.
  • A planned fourth approach — training a custom class-agnostic detection model on a researcher-collected dataset of 20–30 objects labeled under a single "Object" class using AnyLabeling and Roboflow — was designed but not completed in this phase. The partial implementation exists in src/unknown_object_detection/agnostic_nano_owl.py.
